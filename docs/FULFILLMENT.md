# Books attribution contract

This integration is approved for private preview only. Books production code, data, credentials, and deployment remain untouched. QR Studio account setup remains deferred.

## Wire contract v1

- QR redirects append `qr_ref=<base64url JSON>.<base64url HMAC-SHA256>` only for explicitly allowed Books destinations. The payload is `{v:1,codeId,visitId,visitedAt,event,book,placement}`; IDs are UUIDs, visitedAt is ISO UTC, labels are bounded to 160 characters. Sign with server-only `QR_ATTRIBUTION_SECRET`; Books verifies with `BOOKS_QR_ATTRIBUTION_SECRET`. No personal information is included. Maximum age is 24 hours; browser persistence lasts the current tab session. HEAD/bot/prefetch do not receive attribution.
- A private QR preview can replace the Books origin with `QR_BOOKS_PREVIEW_ORIGIN` while retaining path/query/fragment, before appending attribution. This affects only recognized Books origins; it does not rewrite saved destination URLs. Account-free preview checks remain required.
- Books captures the latest valid-looking reference into session storage, removes it from the visible URL, and submits it as optional `qrAttribution`. Server verification is authoritative. Invalid/expired attribution is ignored without weakening normal form validation.
- Books creates an always-on logical request identity when capture is enabled. Capture defaults off outside the explicit preview. It preserves that ID and attribution through queue/error/regional transitions. Existing creation-source fields, validation, approvals, and fulfillment behavior remain unchanged. Retry identity is separate from visit identity.
- QR Studio calls Books `POST /api/qr/report` server-to-server with `Authorization: Bearer <BOOKS_QR_REPORT_KEY>` and body `{codeIds:string[],from:string,to:string,event?:string}`. IDs are constrained to the current workspace by QR Studio; event filters use frozen submission labels. Books additionally restricts its preview/report data to its configured integration. `from` inclusive / `to` exclusive select the originating visit time. Maximum 366 days, 500 code IDs per request (larger workspaces are batched). Never send names, contact details, or full addresses.
- Response: `{version:1,preview:boolean,updatedAt:string,totals:Metrics,byCode:CodeMetrics[],byCountry:Breakdown[],byCity:Breakdown[],coverage:{trackedRequests:number,untrackedDeliveryRequests:number}}`.
- `Metrics`: `{requests:number,booksRequested:number,booksShipped:number,deliveredOrders:number,needsAttention:number}`. `CodeMetrics` adds `{codeId,event,book,placement}`; `Breakdown` adds `{name}`. Requests count logical durable submissions, not HTTP responses, retries, or shipment legs. Card packs are excluded from book units. Books' normalized shipment/delivery evidence remains authoritative. Unknown tracking is not a zero delivery claim.
- QR Studio browser fetches `GET /api/fulfillment?days=30&event=...&codeId=...`; response wraps `{status:"connected"|"unavailable"|"not_configured",report:Report|null,previewOrigin?:string,message?:string}`. A failed refresh preserves the last successful browser report for matching filters with a stale warning.

## Isolated preview storage

Books private preview uses a separately authenticated `books-preview-gateway` in the existing QR Studio Supabase project, backed only by a new preview table. No production Books database keys or provider/email credentials are installed. The server requires `BOOKS_QR_PRIVATE_PREVIEW=1`, Vercel preview environment and exact generated deployment hostname (or explicit loopback development mode). It handles valid public intake with simulated fulfillment and visible preview labeling. It never calls providers, CRM, Sheets, or email.

Gateway actions: `submit` with `{id,submissionId,fingerprint,attribution,books,country,city,status}`; `list` (preview summaries only); `transition` with `{id,status}`; `report` with `{codeIds,from,to}`; `delete` with `{id}` for exact synthetic cleanup. Status is `received|pending|approved|shipped|delivered|failed|rejected|cancelled|waitlisted`. `books` is `{Principles:number,Patterns:number}`. Attribution is the verified wire payload or null. Server owns timestamps and legal transition behavior. Submission replay with the same fingerprint returns the same logical request; conflicting replay returns 409. Gateway credentials are independent of QR scan/workspace/report credentials and never reach the browser.

The payload is flat (`{action:"submit",id,...}`). Submit/transition return `{request:PreviewRequest}`; list returns `{requests:PreviewRequest[]}`. Public preview records contain identifiers, attribution, quantities, coarse destination, status, and timestamps; fingerprints/version counters stay inside the gateway. State updates use optimistic version checks; listing uses keyset pagination. Country-qualified city groups do not merge identically named cities in different countries. Tracking eligibility mirrors Books' maintained PBD/Huboo/India countries; AU/NZ and unsupported destinations cannot simulate shipment/delivery. Update this preview eligibility alongside any future Books routing change.

## Release boundary

Production changes are additive source/migration work on the Books feature branch only. They must be reviewed and separately authorized before applying any migration, merging, deploying, or enabling capture there. Test requests and simulated shipment controls are exclusive to the private preview. No historical attribution inference or customer-data copying is permitted.
